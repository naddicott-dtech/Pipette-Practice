# Mechanic refinements — 2026-05-06

After Chunk C3 shipped, hands-on testing surfaced four mechanic mismatches with how
real micropipettes are used. This is the decision log + implementation summary for
the follow-up that lands on top of C3 (PR #16, merged to main).

## Background

Chunk C3 modeled every interaction (pickup, draw, eject, discard) as a plunger
press with soft/hard outcomes. The 2026-05-05 Decision Log retired
`NOT_LOW_ENOUGH` and `PUNCTURE` because the lock-and-act mechanic dropped
continuous depth control.

User feedback from a Lawrence Livermore-trained tester:

1. **Tip pickup is not a plunger press.** The technique is a quick "tap-tap-tap"
   to seat the tip firmly on the shaft. Pressing the plunger has no effect on
   tip seating in real hardware.
2. **Loading a well needs depth control.** The player has to choose where
   along the well to stop — too high and the sample disperses into the buffer,
   too deep and the tip punctures the agar. After the tip is positioned, the
   plunger press handles dispense as before.
3. **Tip ejection is a separate button.** Real pipettes have a side eject
   button that's not connected to the plunger. One press, the tip flies off.
4. **Drawing has no under-press failure.** A press that stops well short of
   the soft stop should fail (the volume drawn is wrong); current code treated
   anything below the soft tolerance as a silent abort.

## Decisions

### Tap-driven actions (items 1 & 3)

- New `tapCount` field on RuleState / store.
- New `WORKFLOW.TAP_TARGET_COUNT = 3` and `WORKFLOW.TAP_WINDOW_MS = 700`.
- New rule entry points: `tryTapPickup(state, firm)` and `tryTapDiscard(state)`.
- `tryAct` no longer dispatches GET_TIP/DISCARD_TIP — those branches return NOOP
  so a misrouted call is loud. `PlungerAction` reduced to `'draw' | 'eject'`.
- Controller routes Space-down in `locked + GET_TIP` to a tap counter. Three
  taps inside the window → `tryTapPickup(state, true)`. Single tap then timeout
  → `tryTapPickup(state, false)` which advances the workflow with a new
  `LOOSE_TIP` warning. Two taps then timeout → reset count, prompt re-explains.
- `locked + DISCARD_TIP` fires `tryTapDiscard` on the first Space-down.

### LOAD_WELL descent (item 2)

- New interaction phase: `'descending'`. Inserted between `committing` and
  `locked` for LOAD_WELL only.
- New `descentMs` field on RuleState / store. Controller advances it each
  frame in `descending`.
- New `WORKFLOW.DESCENT = { HIGH_TO_GOOD_MS: 600, GOOD_TO_PUNCTURE_MS: 1100,
  AUTO_PUNCTURE_MS: 1500 }`.
- `tryStopDescent(state, descentMs)`:
  - `< HIGH_TO_GOOD_MS` → `NOT_LOW_ENOUGH` failure (reactivated)
  - in good zone → transitions to `'locked'`, plunger press follows
  - `≥ GOOD_TO_PUNCTURE_MS` → `PUNCTURE` failure (reactivated)
- `AUTO_PUNCTURE_MS` is a hard cap — controller fires PUNCTURE if the player
  never presses Space.
- CameraRig advances `committing → descending` for LOAD_WELL, `committing → locked`
  for everything else.
- Pipette.tsx interpolates the body Y from `Y_DESCENT_START` to `Y_DESCENT_PUNCTURE`
  over `descentMs`, so the player can visually track the tip.

**Decision Log amendment:** PUNCTURE and NOT_LOW_ENOUGH are reactivated, scoped
to the LOAD_WELL descent sub-phase only. They do not return as plunger-press
outcomes.

### SHORT_DRAW (item 4)

- New `'short'` outcome from `plungerOutcome`, between `'aborted'` and `'soft'`:
  - `peakDepth < SHORT_OUTCOME_THRESHOLD` (= 0.175, ≈ 1/4 of soft) → `'aborted'`
    (silent — quick exploratory tap)
  - `< SOFT_OUTCOME_THRESHOLD` → `'short'`
- DRAW_SAMPLE 'short' → `SHORT_DRAW` failure (new code).
- LOAD_WELL 'short' is treated as 'aborted' — no failure, no warning, player
  retries.

### Trash mesh (item 5)

- New `Trash.tsx` component: 250 mL beaker (translucent cylinder + bottom
  disc), three pre-existing used tips, a `FlyingTip` animation on each
  successful DISCARD_TIP, and a "Waste tips" label.
- TRASH target moved to `[-5, 0, -2.5]` (the top-left zone behind the tip
  rack in the OVERVIEW camera).

## Failure / warning taxonomy after the follow-up

Failures (6): `NO_TIP`, `HARD_STOP_TO_DRAW`, `EMPTY_EJECT`, **`SHORT_DRAW`**,
**`NOT_LOW_ENOUGH`**, **`PUNCTURE`**.

Warnings (4): `SOFT_STOP_TO_EJECT`, `NO_FRESH_TIP`, `WRONG_TUBE`,
**`LOOSE_TIP`**.

`failures.test.ts` enforces the count, copy completeness, and disjointness of
the two sets.

## Test coverage

- `rules.test.ts` — full rewrite of pickup/discard sections; new `tryTapPickup`,
  `tryTapDiscard`, `tryStopDescent`, `tryAct routing`, and SHORT_DRAW test cases.
  Integration test threads through tap pickup → plunger draw → descent → plunger
  eject → tap discard.
- `plunger.test.ts` — new bands: `'aborted'` only below SHORT, `'short'` between
  SHORT and SOFT, `'soft'` band unchanged, half-press classifies as `'short'`.
- `prompt.test.ts` — new `descending` test, locked GET_TIP triple-tap copy
  (with tapCount progress), locked DISCARD_TIP single-tap copy.
- `config.test.ts` — new invariants on the threshold ordering and descent timings.
- `failures.test.ts` — count expectations updated to 6 + 4.
- `store.test.ts` — `descentMs` and `tapCount` reset coverage; tryAct round-trip
  test switched to `tryTapPickup`.

## Not done in this follow-up

- "Slow vs. hard eject" rate modeling — user explicitly said skip.
- Touching the well wall to verify position before dispense — left for a real-lab
  exercise, not modeled here.
- Tap-driven mechanic is keyboard-only. Click commit is unchanged; clicking on
  the canvas in `locked` GET_TIP / `locked` DISCARD_TIP currently does nothing
  because the mouse-down listener gates on `'free'`. If we want tap parity for
  click input we'd add an in-HUD "Tap" button in a later chunk.
